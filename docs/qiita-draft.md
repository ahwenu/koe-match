# 話して始めるマッチングアプリ「Koe Match」を作る

> Qiita向けの未公開下書き。開発中に確認した内容を日付ごとに追記する。

## 2026年11月23日｜企画からスマホ版の実装へ

ハッカソンのテーマは「話すだけで、誰かの面倒を減らす」。家事、カフェ業務、一人暮らしの場面を洗い出したあと、打ち合わせで音声を使ったマッチングアプリに企画を決めた。減らしたい手間は、プロフィールを文章にまとめることと、会う前に相手との会話を想像すること。声や話の内容を相手選びの材料にし、初対面で聞いてみたいことを仮想デートで見つけられるようにしたい。

打ち合わせの長い書き起こしと、その後に話して伝えた開発指示は、Aqua Voiceで入力したテキストとしてCodexに渡した。話が前後する書き起こしから、企画の狙い、デモの３機能、担当範囲、未決事項を抜き出した。ここでのAqua Voiceの実利用は、アプリを作るための素材や指示を話して入力したこと。

### 既存実装から参考にしたこと

[Secret Tenderの既存リポジトリ](https://github.com/Jun0908/ethglobal-mumbai-2026-AIBot/tree/3c4ea47)を取得し、コミット `3c4ea47` のREADME・会話API・分岐処理を読んだ。既存版はNext.jsのWebアプリで、自由な返答のうち意図が明確なものだけを、用意した場面の進行につなげていた。この設計を参考に、新しく取得した [Koe Matchのリポジトリ](https://github.com/ahwenu/koe-match) にReact Native（Expo）でスマホ版を作り始めた。

### デモの３機能

| 機能 | 企画時に想定した体験 |
| --- | --- |
| 音声プロフィール | 自己紹介や今日の出来事を話して記録する。記録から紹介文を作り、読み上げを聞いてから内容を承認する。 |
| 声で相手を選ぶ | 架空の成人候補２人のサンプル音声を左右で聞き比べ、好みの側をスワイプする。選んだ候補の仮想デートに進める。 |
| 仮想デート | 待ち合わせ、予定変更、別れ際の３つの場面を会話で練習する。返答で場面が分岐し、最後に実際の会話で使える質問の例が残る。 |

開発は、プロフィール、候補選び、仮想デートを複数のエージェントで並行して担当。メイン側では共通の画面部品と型、ナビゲーション、保存や音声を統合する。仮想デートの分岐ロジックは、４経路と、曖昧な返事で場面が進まないことを確認した。

### 企画時に決めたAqua Voiceの使い方

アプリでは、iPhoneのAqua Voiceキーボードをプロフィールや仮想デートの入力欄で使う設計。発話が文字として入ったあと、本人の操作で記録または返答を確定する。iPhoneのAqua Voiceキーボードを使った発話入力は、引き続き実機で確認する。[Aqua Voice公式ガイド](https://aquavoice.com/ja/guide)

### 2026年11月23日｜デモ３機能の統合

Expo SDK 58のアプリに３機能を統合した。プロフィールでは自己紹介や日記を保存し、紹介文の下書きを端末内で作成する。自分で編集し、端末の合成音声で試聴してから承認できる。「見つける」では架空の成人候補４人をサンプル音声で比べ、スワイプかボタンで選ぶ。仮想デートでは待ち合わせから別れ際までの３場面をタップやテキスト入力で進め、最後に実際に会ったときの質問例を見返せる。相互の興味はデモ用の設定で、実ユーザー間のマッチングは今後の設計項目。

デモの基本経路は外部サービスの設定なしで使える構成にした。オプションのローカル開発用APIには、OpenAIによる紹介文の草案生成と仮想デートの自由質問への返答、ElevenLabsによるiOSでの録音・同意後の登録・試聴・削除の経路を用意した。候補のサンプル音声はIrodori-TTSで用意した。APIキーは開発用サーバー側で扱う。

`npm run typecheck` と `npm run lint` は通過した。今回の実行環境からはCoreSimulatorに接続できず、シミュレーターでの通し動作は確認できなかった。

次はiPhoneでAqua Voiceキーボードを使い、プロフィールに話して入力するところから仮想デートの終了まで通す。文字起こしを確認して追加・送信する操作、音声の聞き比べ、途中で迷った箇所を記録する。OpenAIとElevenLabsの実サービスを使った通し動作と、XcodeでのiOS配布アーカイブも確認が残っている。


### ３機能の統合と確認方法

候補の音声は４人分をそれぞれ左右に定位させ、左右８本の素材としてアプリに同梱した。端末のスピーカーだけで定位が分かりづらい場合に備え、どの側の声を再生しているかを画面にも表示する。候補選びはボタンでも操作でき、音声の書き起こしも読める。

プロフィールでは、発話の記録、紹介文の生成、試聴、本人による承認を別の操作にした。仮想デートでは、明確な選択だけで場面を進める。外部AIを設定した場合も、自由な発話への返答と場面の進行は独立して扱う。

型チェックとExpoのiOS・Android・Web向けバンドル出力を確認した。外部サービスを模擬したAPIテストでは、紹介文と会話の生成、音声の重複登録防止、試聴、登録削除を確認した。実際のサービスへの音声送信は行っていない。
