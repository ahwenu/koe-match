# 話して始めるマッチングアプリ「Koe Match」を作る

> Qiita向けの未公開下書き。開発中に確認した内容を日付ごとに追記する。

## 2026年11月23日｜企画からスマホ版の実装へ

ハッカソンのテーマは「話すだけで、誰かの面倒を減らす」。家事、カフェ業務、一人暮らしの場面を洗い出したあと、打ち合わせで音声を使ったマッチングアプリに企画を決めた。減らしたい手間は、プロフィールを文章にまとめることと、会う前に相手との会話を想像すること。声や話の内容を相手選びの材料にし、初対面で聞いてみたいことを仮想デートで見つけられるようにしたい。

打ち合わせの長い書き起こしと、その後に話して伝えた開発指示は、Aqua Voiceで入力したテキストとしてCodexに渡した。話が前後する書き起こしから、企画の狙い、デモの３機能、担当範囲、未決事項を抜き出した。ここでのAqua Voiceの実利用は、アプリを作るための素材や指示を話して入力したこと。

### デモの３機能

| 機能 | 企画時に想定した体験 |
| --- | --- |
| 音声プロフィール | 自己紹介や今日の出来事を話して記録する。記録から紹介文を作り、読み上げを聞いてから内容を承認する。 |
| 声で相手を選ぶ | 架空の成人候補２人のサンプル音声を左右で聞き比べ、好みの側をスワイプする。選んだ候補の仮想デートに進める。 |
| 仮想デート | 待ち合わせ、予定変更、別れ際の３つの場面を会話で練習する。返答で場面が分岐し、最後に実際の会話で使える質問の例が残る。 |

開発は、プロフィール、候補選び、仮想デートを複数のエージェントで並行して担当。メイン側では共通の画面部品と型、ナビゲーション、保存や音声を統合する。仮想デートの分岐ロジックは、４経路と、曖昧な返事で場面が進まないことを確認した。

### 企画時に決めたAqua Voiceの使い方

アプリでは、iPhoneのAqua Voiceキーボードをプロフィールや仮想デートの入力欄で使う設計。発話が文字として入ったあと、本人の操作で記録または返答を確定する。iPhoneのAqua Voiceキーボードを使った発話入力は、引き続き実機で確認する。[Aqua Voice公式ガイド](https://aquavoice.com/ja/guide)

### 2026年11月23日｜デモ３機能の統合

Expo SDK 58のアプリに３機能を統合した。プロフィールでは自己紹介や日記を保存し、紹介文の下書きを端末内で作成する。自分で編集し、端末の合成音声で試聴してから承認できる。「見つける」では架空の成人候補４人をサンプル音声で比べ、スワイプかボタンで選ぶ。仮想デートでは待ち合わせから別れ際までの３場面をタップやテキスト入力で進め、最後に実際に会ったときの質問例を見返せる。相互の興味はデモ用の設定で、実ユーザー間のマッチングは今後の設計項目。

デモの基本経路は外部サービスの設定なしで使える構成にした。オプションのローカル開発用APIには、OpenAIによる紹介文の草案生成と仮想デートの自由質問への返答、ElevenLabsによるiOSでの録音・同意後の登録・試聴・削除の経路を用意した。候補のサンプル音声はIrodori-TTSで用意した。APIキーは開発用サーバー側で扱う。

候補の音声は４人分をそれぞれ左右に定位させ、８本のステレオ素材として同梱した。画面には再生中の側を表示し、ボタンでの選択と自己紹介の文字表示にも対応した。プロフィールは下書きを自分で確認してから承認する。仮想デートは明確な選択だけで場面を進め、外部AIを設定した場合の自由な質問への返答は、場面の進行と独立させた。

`npm run typecheck`、`npm run lint`、ExpoのiOS・Android・Web向けバンドル出力、XcodeでのiOSシミュレーター用ビルドが通過した。iPhone 17のシミュレーターでは、アプリを起動して候補比較画面が表示されることを確認した。モバイル幅のChromiumでは、左右の音声の連続再生と停止、候補選びのスワイプ、３回の比較、仮想デートの完了と振り返り、プロフィールの承認状態が再読み込み後も残ることを確認した。外部サービスを模擬したAPIテストでは、紹介文と会話の生成、音声の重複登録防止、試聴、登録削除を確認した。

### 2026年11月23日｜ローカルiOSシミュレーターでの確認

Xcodeで開発ビルドを作り、MacのiPhone 17シミュレーター（iOS 27.0）にインストールした。「見つける」の初期画面で、２人の候補と３つのタブが表示されることを確認した。開発時の動作確認はPCのシミュレーターで行い、ユーザーの実機を使う検証は明示の指示がある場合に行う。

Aqua Voiceキーボードで実際に話し、プロフィール入力から仮想デートまで通す検証は残っている。実機での検証時には、文字起こしを確認して追加・送信する操作や迷った箇所を記録する。OpenAIとElevenLabsの実サービスを使った検証も残っている。

### 2026年11月23日｜声の方向が分かる比較画面

２人の声の方向を画面でも追えるよう、中央に丸みのある招き猫、左右に音波とそれぞれの候補情報を配置した。候補の表示は名前と自己紹介を中心にし、候補決定後や仮想デートでは丸い頭文字のマークを使う。左右の候補は引き続きスワイプでもボタンでも選べる。

iOSシミュレーターのXCUITestでは、比較画面とプロフィールの行き来、スワイプとボタンでの候補選び、仮想デート３場面から振り返りまでの動作を確認した。

### 2026年11月23日｜２つの声が重なる起動画面

離れた位置にある紫と橙の円形の波形が近づいて重なり、軽く脈打つ演出を加えた。アプリを新しく起動したときに再生する。端末で動きを減らす設定を選んでいるときは、重なった状態から表示する。「はじめる」は演出の途中でも押せて、候補の比較へ進める。

iOSシミュレーターの録画で、２つの波形が離れた状態から斜めに近づき、重なって２回脈打ったあとに静止するところまで確認した。「はじめる」から比較画面への遷移はXCUITestで確認した。

### 2026年11月23日｜デート練習のAqua Voice入力

「話して返事」を押すと、入力欄が表示されたあとにキーボードを開くようにした。iPhoneでは地球儀キーでAqua Voiceに切り替え、シミュレーターではMac版で入力するか、履歴から文字起こしをコピーして貼り付ける。

ローカルのiPhone 17シミュレーターでXCUITestを実行し、マイク操作でキーボードが現れ、合成した日本語の番号入力を標準のペーストメニューから挿入して送ると、次の場面へ進むことを確認した。Aqua Voiceによる実際の発話認識と自動挿入の確認は残っている。[Aqua VoiceのiPhone設定手順](https://aquavoice.com/guide/getting-started-iphone)

### 2026年11月23日｜Voice-matchingの音源を採用し、ライト・ダークで通し検証

上流で採用済みの４音源をExpo版に取り込み、名前、台詞、VOICEVOXのクレジットを比較画面に表示した。左右用の８本を検査し、再生側のPCMが原音とバイト単位で一致し、反対側は無音であることを確認した。[音源とクレジットの取り込み記録](voice-matching/integration.md)

自己紹介では文章を残したままキーボードを閉じられるようにした。比較の「次」は再生の終了後も最後に聴いた側を参照し、仮想デートは「２番でお願いします」のように丁寧な番号指定を受け付けるようにした。

ローカルXcodeで開発ビルドを作り、iPhone 17シミュレーターのライト表示で、起動、自己紹介と承認、試聴、３回の比較、マッチ、公園での練習と振り返りまでのXCUITestが通過した。比較の途中経過・確定結果・選び直しの状態を再起動後に確認した。ダーク表示では６か所すべてで３場面と場所別の質問に到達した。「次」は左の再生が自然終了したあとに右を聴く操作を、「２番でお願いします。」は選択肢で場面を進める操作を、テスト用テキストを貼り付けて確認した。

モバイル幅のChromiumでは、左の音源の再生終了後、「次」を入力して右を再生できることを確認した。型チェックとLint、iOS・Android・Web向けのExpo出力は通過した。アプリの音声入力はテスト用テキストで検証しており、Aqua Voiceキーボードで実際に話した結果と、実機でのイヤホン試聴は今後確認する。

### 2026年11月23日｜聴きくらべとマッチ成立に効果音を追加

OtoLogicの「ボタン ポチッ01-1」と「キラキラ02-1」を取得し、選択音は0.25秒、成立音は0.84秒に切り出して音量を調整した。候補の声を止めてから選択音を鳴らし、3回目の選択で新しくマッチが成立したときにチャイムを鳴らす。比較画面と成立画面のクレジットからライセンスを確認できる。 [OtoLogicの利用規約](https://otologic.jp/free/license)

モバイル幅のChromiumでは、タップ、スワイプ、方向を示すテスト用テキストでそれぞれ選択音が最初から最後まで再生され、新しいマッチで成立音が1回鳴ることを再生イベントで確認した。候補の試聴が選択音より先に止まること、保存結果や履歴からマッチを開き直しても成立音が再生されないことも確認した。Aqua Voiceキーボードでの発話はテスト用テキストで模擬した。

Xcodeでの開発ビルドが通過した。iPhone 17シミュレーターのXCUITestでは、候補の試聴、3回の選択、マッチ成立、クレジット表示、履歴からの再表示を確認した。型チェックとLint、iOS・Android・Web向けのExpo出力も通過した。端末やイヤホンでの聞こえ方は今後確認する。

### 2026年11月23日｜効果音を入れたiOS版の通し検証

ローカルのiPhone 17シミュレーター（iOS 27.0）をXCUITestで操作した。ライト表示で候補の試聴、タップ・スワイプ・文字入力での3回の選択、再起動後のラウンドの復元、マッチ成立と公園でのデート練習から振り返りまで確認した。開発用の再生イベントで、各操作の0.25秒の選択音と0.84秒の成立音が終了まで再生されたことを確認した。ダーク表示では初回のマイク許可、自己紹介の練習録音と試聴、画面を離れた後の一時録音の破棄、聴きくらべに戻っての再生を確認した。

3回目の選択直後に履歴の詳細を開くと、新しい成立音が過去の結果の上で鳴った。成立音は聴きくらべ画面を表示中のときに鳴らすよう修正し、履歴を開いた場合も新しい結果が保存され、表示中の履歴では成立音が鳴らないことを確認した。デート練習を途中で終了するか場所選択へ戻ると読み上げが続いたため、この2操作で停止するようにした。最後まで練習した場合の締めの返答は、引き続き読み上げることを確認した。

Aqua Voiceキーボードから入る文字はテスト用テキストで代用した。実際の発話認識とイヤホンでの音量・音色は検証対象に含めていない。
