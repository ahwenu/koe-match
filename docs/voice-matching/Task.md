# VOICE MATCH 開発タスク

「見た目の前に、声でつながる。」

一人暮らしの会社員が、通勤後や休日にイヤホンで二人の声を聴き比べ、「この人の声をもっと聴きたい」と思った相手に関心を送れる、日本語のモバイル向けWebアプリを作る。

**最初のリリースの完成条件**は、スマートフォンで「左右を試聴 → 好みを選択 → 次のペア → 傾向を確認」を一巡でき、自分の声も録音・再生できること。ページを開き直しても比較履歴と保存した録音が残ること。このファイルは実装前の仕様と作業リストで、チェックは動作確認後に付ける。

## 1. プロジェクト構成

Next.js（App Router）、TypeScript、Tailwind CSS を使用する。ブラウザ標準の Web Audio API、MediaRecorder API、IndexedDB を利用する。ディレクトリ案は以下のとおり。

```text
VoiceMatching/
├── Task.md
├── src/
│   ├── app/                # / は比較。その他の画面は次表のパスに配置
│   ├── components/         # 左右のプレイヤー、波形、選択ボタン、録音操作
│   ├── features/
│   │   ├── comparison/     # ペアの生成、左右の割り当て、選択履歴
│   │   ├── recording/      # マイク、録音、プレビュー
│   │   ├── preferences/    # 履歴から傾向を集計
│   │   └── matching/       # 関心、相互成立、公開希望
│   ├── data/               # デモ音声の目録、質問、デモ用の相互関心データ
│   └── lib/                # 音声再生と端末内保存
└── public/audio/demo/      # アプリに採用した試聴用音声
```

## 2. 画面設計

| 画面 | 主な操作と表示 |
| --- | --- |
| オンボーディング `/welcome` | コンセプトの紹介、ニックネーム・基本情報・希望条件の入力。イヤホン試聴を案内し、比較へ進む。デモは録音前でも試せる。 |
| 声の録音 `/record` | 自己紹介または質問を選び、録音時間を見ながら録音。再生・再録音・公開前プレビューを経て保存する。 |
| 二択比較 `/` | 進捗「1 / 5」、LEFT・RIGHTのプレイヤー、波形、四つの選択肢を表示。最後の選択後は好み分析へ進む。 |
| 好み分析 `/insights` | 比較回数、最近の選択、好んだデモ音声に多い特徴を表示。比較前には開始ボタンを表示する。 |
| マッチング `/matches` | 気に入った候補に関心を送る。送信済みと相互成立を区別し、成立したデモ相手を確認できる。 |
| プロフィール・設定 `/profile` | 録音の再生・差し替え・削除、プロフィールの公開設定、希望条件、ステレオ定位の切り替え、候補の非表示を管理する。 |

比較画面をデザインの基準にする。ダーク背景に、左はブルー、右はピンク、進捗にはパープルを使う。写真は表示しない。狭い画面でも左右の位置は保ち、再生中の側は色・波形・「再生中」の文字で分かるようにする。選択ボタンは親指で届く位置に置き、動きを減らす設定では波形と画面遷移のアニメーションを抑える。

## 3. 実装タスク

### ① デモ音声と二択比較を先に通す

**デモ用の合成音声を作る場合**は、親フォルダにある CosyVoice3 の日本語生成環境を使う。以前の制作で、選定した1人の参照音声から日本語の自己紹介を生成し、採用テイクを保存している。ブラウザには採用済み音声を配信する。

- [ ] 既存スクリプト `../scripts/cosyvoice3_japanese_zero_shot.py` の台本と参照音声の読みは以前の作品用に固定されている。VOICE MATCH 用の生成入口では、利用できる参照音声、その正確な読み、話してほしい台本と読みを個別に指定できるようにする。
- [ ] まず異なる2声で同じ短い自己紹介を生成し、読み間違い、語尾の欠落、間の自然さ、イヤホンでの聞き取りやすさを試聴する。音量をそろえて左右を入れ替えても比較できることを確認してから、採用する声を増やす。画面には「合成デモ音声」と表示する。

- [ ] 既存の `../voice-younger-vc/pairs/common-voice-ja-20s/` にある日本語音声から、話者IDの異なる10人分を選び、最初の5組を用意する。以前の確認では保存先の重複を除いて40人分。デモ用の目録に話者ID、出典、長さ、音声の特徴、使用ファイルを記録する。
- [ ] 候補は「デモ音声」と表示する。読み上げサンプルを実在会員の自己紹介として扱わない。配布用に収録する音声は利用条件を確認し、必要に応じて自作サンプルへ差し替える。
- [ ] 試聴素材のラウドネスをそろえ、音割れを確認する。各セッションの開始時に候補をシャッフルして組を作り、左右の割り当てを保存する。同じ話者同士を組にしない。
- [ ] タップした側だけを Web Audio API で再生し、左右に軽く定位させる。別の側を押したら先の音声を止める。停止・再再生、再生位置に連動した波形、終了時の状態更新を実装する。定位を切った場合は中央で再生する。
- [ ] 「左が好き」「右が好き」「どちらも好き」「どちらでもない」を実装する。選択したら一度だけ記録し、再生を止めて次へ進む。読み込み失敗時は再試行できるようにする。

### ② 履歴保存と好み分析

- [ ] セッションID、ペア番号、左右の話者ID、選択、日時を保存する。再読み込み時は同じ進捗から再開し、最後の回答後は結果画面を復元する。
- [ ] 初版はローカル集計で「ゆっくり」「落ち着いた声」「明るい話し方」などの音声タグ別の傾向を表示する。各タグの提示件数と選択件数を併記し、「両方」は双方を選択、「どちらでもない」は双方を未選択として数える。最初の数件は件数を中心に見せる。
- [ ] 傾向の説明は声や話し方について書く。価値観や人柄を紹介するときは、本人の回答・プロフィールを参照する。将来のAI分析は同じ履歴を入力にできるよう、集計処理を画面から分ける。

### ③ オンボーディング・録音・設定

- [ ] 自己紹介と質問への回答を別々に保存する。初版の質問は「休日はどんなふうに過ごしますか？」「恋人とどんな時間を過ごしたいですか？」「最近うれしかったことは何ですか？」から提示し、質問生成は後からAIに接続できるようにする。
- [ ] ユーザーの操作でマイクを起動し、15〜30秒の音声を録音する。経過秒数を表示し、30秒で自動停止する。15秒未満の場合は録り直しを案内する。端末が対応する録音形式を選び、停止・画面離脱時はマイクを解放する。
- [ ] 公開前に試聴と再録音ができるようにする。保存を確定するまで既存録音を保持し、録り直しを取り消しても元に戻れるようにする。
- [ ] 比較履歴・設定には localStorage、録音本体には IndexedDB を使う。録音は初期値を非公開とし、端末内デモでの公開状態を明示する。マイク拒否、非対応ブラウザ、容量不足時には、利用者が次に取れる操作を示す。

### ④ 関心とマッチング

- [ ] 好きと回答した候補を見返し、利用者の操作で関心を送れるようにする。二重送信を防ぎ、相手側のデモデータにも関心がある場合だけマッチ成立にする。
- [ ] 成立後の拡張先をテキストチャット、音声メッセージ、音声通話とする。写真は双方の公開希望がそろった相手にだけ表示する設計とし、本番接続時にサーバー側で判定する。
- [ ] 初版は端末内デモとして完結させる。本番のアカウント、公開配信、ユーザー間の通信、AI質問生成・推薦は次段階の対象とする。

## 4. 依存関係と起動方法

実装時に Next.js が対応する Node.js の LTS バージョンと npm を決め、使用バージョンとロックファイルを保存する。実行に必要な主なパッケージは `next`、`react`、`react-dom`、開発用は TypeScript、Tailwind CSS と対応する PostCSS プラグイン、ESLint、React・Node.js の型定義。初版の試聴・録音・集計には外部APIキーを必要としない。

以下は実装後に提供する起動手順。PowerShell でプロジェクトに移動し、依存関係を入れて起動する。

```powershell
Set-Location -LiteralPath 'D:\Codex\Voice Experiments\VoiceMatching'
npm ci
npm run dev
```

PCでは `http://localhost:3000` を開く。スマートフォンの実機で録音を試す際は、端末が信頼するHTTPSの検証URLを使う。実装完了時に、使用したNode.jsのバージョン、実際の起動手順、実機で試した範囲を記録する。

## 5. 受け入れ確認

| 確認 | 合格条件 |
| --- | --- |
| 試聴 | 左→右を素早く押しても声が重ならない。停止・再再生でき、イヤホンで左右定位と中央再生を確認できる。 |
| 比較 | 四つの選択がそれぞれ正しく記録される。連打しても一組だけ進み、5組終了後は結果が表示される。 |
| 復元・分析 | 比較途中で再読み込みしても候補・左右・進捗が維持される。選んだ話者数と画面上の集計が一致する。 |
| 録音 | スマートフォンで録音、試聴、再録音、保存ができる。再起動後も再生でき、非公開への変更と削除が反映される。 |
| マッチ | 片方だけの関心は送信済み、双方なら成立となる。再読み込みしても重複しない。 |
| モバイル | iOS Safari・Android Chromeを検証対象とする。幅360pxで横スクロールせず、タップ・画面読み上げで左右を識別できる。実機とエミュレーターの確認結果は区別して記録する。 |
| ビルド | クリーンインストール後に `npm run lint` と `npm run build` が通り、起動後に比較から結果表示まで操作できる。 |
